# 1단계 설계 — 2026-09-30

## 범위와 전제

한국 세법상 거주 개인이 보유한 한국 상장주식/ETF, 미국 상장주식/ETF와 현금을 데이터화합니다.
미국 자산의 한국 과세 및 외국 원천징수를 기록하는 구조이며, 미국 납세자의 미국 소득세 전체를
계산하는 시스템은 아닙니다. `residency`와 `us_tax_person`으로 향후 엔진에서 지원 대상 여부를
검사할 수 있습니다. 현재는 계산 엔진 자체가 없습니다.

ISA는 중개형을 전제로 합니다. 연금저축은 증권사 연금저축펀드 계좌를 전제로 합니다.
비상장주식, 장외거래, 직접 채권, 펀드, 부동산, 파생상품은 이번 버전의 자산 타입에서 제외합니다.
현재 데이터 모델의 거주지 속성은 기본 프로필입니다. 연중 거주자 지위 변경은 별도의 이력 설계가 필요합니다.

## 테이블과 관계

| 테이블 | 데이터 및 추가 이유 |
|---|---|
| taxpayers | 납세자, 한국 거주 여부, 미국 납세자 여부. 복수 증권사 계좌의 연간 합산 키 |
| taxpayer_years | 연도별 총급여·종합소득. 연금 납입 세액공제 판정에 사용할 입력 |
| accounts | 증권사·계좌 종류·ISA 일반/서민/농어민형·개설/만기/해지일 |
| instruments | 티커·종목명·시장·통화·주식/국내주식형ETF/기타ETF·연금 매수 가능 여부 |
| holdings | 계좌×자산의 현재 수량·평균 매수가·원화 잔여 취득원가·시세·환율·평가시각 |
| cash_balances | 통화별 현금과 환율. 향후 순자산에 예수금이 빠지지 않도록 분리 |
| transactions | 거래 종류·체결/귀속일·거래통화·금액·수수료·환율·중복 방지용 증권사 식별자 |
| tax_events | 연도·소득 종류·경제적 손익·과세 산입액·국내/해외 원천징수·적용세율·근거 |
| tax_policies | 적용기간·검증상태·공식 근거 URL·정책 파라미터 |
| pension_contributions | 개인납입/퇴직금이체/ISA이체와 공제받은 납입원금 기록 |

`taxpayers → accounts → holdings/transactions/cash_balances` 관계입니다.
`instruments → holdings/transactions`로 종목을 공유합니다.
`transactions → tax_events/pension_contributions`로 원거래를 추적합니다.
`tax_events → tax_policies`로 적용한 정책 버전을 추적합니다.

Holdings에 티커와 종목명을 중복 저장하지 않습니다. `holdings_detail` 뷰가 계좌 정보, 티커,
시장, 종목명과 보유 데이터를 함께 제공합니다. 티커는 숫자형이 아닌 문자열이며 `005930`의
선행 0이 보존됩니다. 세금 계산 결과를 Holdings에 저장하지 않아 시세/정책 변경 후 오래된 결과가
실제 자산 금액처럼 남는 것을 방지합니다.

## 금액과 귀속연도

- Python 가격·수량·환율·세율은 `Decimal`입니다. float, NaN, 무한대와 6자리 초과 소수는 거부합니다.
- DB 가격·수량·환율은 1,000,000배 정수입니다. `10.5주 → 10,500,000`, `$180.25 → 180,250,000`입니다.
- DB 세율은 ppm 정수입니다. `22% → 220,000`입니다.
- 세무 집계용 원화 금액은 정수 원입니다. 환산/원단위 절사 시점은 2단계 계산 정책에서 결정합니다.
- 가격·수량·환율의 곱은 Python Decimal에서 계산해야 합니다. SQL 곱셈은 64bit 정수 범위를 넘을 수 있습니다.
- 현재가가 없어도 보유 데이터를 저장할 수 있습니다. 현재가/환율/평가시각은 전부 존재하거나 전부 비어야 합니다.
- 취득원가는 매입 당시 환율과 인정 수수료를 반영한 **남은 수량의 원화 원가**입니다.
  현재 환율로 평균 달러 매수가를 다시 환산해 과거 취득원가를 덮어쓰지 않습니다.
- 평균매수가만으로 세금 원가를 확정하지 않습니다. 개별 매수거래는 transactions에 남기고,
  이후 엔진의 원가법(FIFO/이동평균/증권사 확정자료) 선택 및 매칭이 필요합니다.
- `recognized_on`은 수입자가 제공하는 결제/지급 기준 귀속일입니다. 자동으로 체결일을 사용하지 않습니다.
  tax_events의 날짜와 계좌는 원거래와 복합 외래키로 일치해야 하며 연도는 DB에서 자동 생성됩니다.
  예: 2026-12-31 체결, 2027-01-04 귀속이면 2027년 이벤트입니다.

## 과세 분류와 기본 가정

`TaxParameters`에는 요청한 22%, 250만원 공제, 국내 일반 금융소득 원천징수 15.4%,
ISA 200/400만원 및 초과 9.9%, 금융소득 기준 2,000만원, 연금수령 기본 연령대별 5.5/4.4/3.3%를
**초기 시뮬레이션 가정**으로 정의했습니다. DB 초기화는 정책을 자동으로 등록하지 않습니다.
정책은 기본적으로 DRAFT이고, VERIFIED는 검증일과 출처가 필수입니다.
서로 다른 정책 코드와 SCENARIO로 가정 변경 실험을 분리할 수 있습니다. 같은 코드의 적용기간은 중복될 수 없습니다.

세율 필드만으로 최종 세액을 확정할 수 없습니다. 실제 세법 및 상품 특례를 판정하고 과세산입액을
확정하는 작업은 2단계의 책임입니다. 금융투자소득세를 현재 시행하는 세목으로 자동 적용하지 않습니다.

TaxTreatment의 의미:

| 값 | 사용 목적 |
|---|---|
| STOCK_CAPITAL_GAIN | 주식 양도소득세 대상. 모든 납세자 계좌 합산 후 기본공제 적용 |
| FINANCIAL_INCOME | 일반 이자/배당 등 금융소득. 국내 상장 해외 ETF 과세소득도 이 그룹일 수 있음 |
| EXEMPT | 비과세 산입액 0을 명시. 모르는 금액 NULL과 구별 |
| ISA | ISA 계좌 단위·계약기간 단위 손익통산 대상 자료 |
| PENSION_DEFERRED | 연금계좌 안의 과세이연. 즉시 인출 가능한 세후 현금으로 처리하지 않음 |
| SEPARATE_DIVIDEND | 2026년 고배당기업 배당 등의 별도 분리과세 판정 결과를 기록할 공간 |
| REVIEW_REQUIRED | 기본값. 판정 전이며 향후 엔진에서 자동 확정 계산을 막아야 함 |

`economic_income_krw`는 경제적 손익이고, `taxable_income_krw`는 해당 과세 체계에
산입되는 금액입니다. 두 값이 같다고 가정하지 않습니다. ISA 비과세 주식 차익은 별도 제외하고,
법적으로 통산 가능한 손실만 ISA 산입액에 반영해야 합니다. ISA 산입액 계산과 국내 ETF 과표기준가
데이터 수집은 2단계의 추가 설계 범위입니다. NULL은 자료 부족이며 0으로 바꾸면 안 됩니다.

국내 상장주식의 일반 소액주주 장내 양도차익 비과세와 국내 상장 해외 ETF의 금융소득 과세를
시장 KR만으로 구분할 수 없으므로 자산 타입을 분리했습니다. 국내 과세대상 주식과 국외주식은
손익통산과 기본공제 공유가 가능한 경우가 있지만 비과세 국내주식 손실을 국외주식에 통산하지 않습니다.
이번 버전은 대주주 판정/특수관계인 정보를 자동 산정하지 않습니다.

해외 배당에는 국가별 조세조약 및 외국납부세액 관련 판정이 필요하므로 국내 15.4%를
일괄 적용하지 않습니다. 실제 국내 원천징수와 외국 원천징수를 별개로 저장하고, 종합과세 추가세액이나
외국납부세액공제를 데이터 입력 단계에서 원천징수액으로 섞지 않습니다.

연금 납입 중 개인납입, 퇴직금 이체, ISA 만기 전환을 구분합니다. `credit_claimed_krw`는
공제세액 자체가 아니라 **세액공제 받은 납입원금**입니다. 실제 환급액, 공제율과 한도는 2단계에서 계산합니다.
퇴직금이체를 개인납입 공제 대상 원금으로 표시할 수 없습니다. 연금수령액의 퇴직금/공제원금/미공제원금/
운용수익 구분과 중도해지 계산은 수령 이력 스키마를 추가하는 후속 단계입니다.

## 검증과 마이그레이션 경계

STRICT 테이블, 외래키, CHECK, UNIQUE, 트리거로 관계와 계좌 제한을 검증합니다.
미국 직접투자 자산은 절세계좌에 넣을 수 없습니다. 연금에는 직접 주식을 넣을 수 없고,
국내 상장 ETF도 `pension_eligible=True`인 상품만 허용합니다. 레버리지/인버스 등의 개별 상품
가능 여부와 IRP 위험자산 한도까지 이 플래그 하나가 검증하지는 않습니다.

Pydantic은 날짜, 타임존, 단위 범위, 세부 값의 형태를 검증합니다. raw SQL은 이 계층을 우회할 수
있으므로 지원되는 입력 경로는 `db.insert()`입니다. DB도 주요 관계와 날짜 무결성을 별도로 검사합니다.
납세자별 ISA 가입자격, 3년 유지요건, 입금한도, 중도해지 추징, 미국 납세자 지위와
복잡한 세액공제/종합과세 판정은 계산 엔진 단계에서 추가합니다.

거래·세금 이벤트·납입내역·정책 버전은 UPDATE로 덮어쓸 수 없습니다.
잘못 가져온 자료는 트랜잭션 안에서 의존 이벤트를 삭제한 후 원거래를 삭제하고 다시 가져옵니다.
법정 수준의 감사 로그나 정정 버전 관리는 후속 구현입니다. 현재 구조를 감사 불변 원장으로 간주하지 않습니다.
보유 스냅샷과 현금은 향후 갱신 가능하며 이번 단계에서는 읽기·최초 저장 API만 제공합니다.
